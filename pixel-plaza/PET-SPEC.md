# 3D 辦公室寵物規範（以「辦公室流浪貓」為範本）

> 這份是寵物系統的完整規格：角色繪製流程、角色機制、互動功能、多人同步、後端、除錯、已知限制，全部記錄在這裡。
> 第一款寵物是**三花貓**（目前名字「無名小貓」，由全員投票取名）。之後要做**第二款（寵物狗等）**時：
> - 第 1～9 章是「寵物共通規範」，可直接沿用（流程、資料格式、UI、同步、後端協定）。
> - 第 10 章列出**貓與狗必然不同**的地方與建議做法（狗的習慣不同，呈現方式也要不同）。
> - 第 11 章是「做新寵物的檢查清單」。
>
> 相關文件：`MAINTENANCE.md` §11（貓的維護筆記、逐次修改）、`UI-SPEC.md` §9.5（貓的 UI 規範）、根目錄 `MAINTENANCE_LOG.md`（修改紀錄）。
> 程式全部在 `pixel-plaza/index.html`（單檔 three.js），貓的區塊在 `tick()` 之前的「辦公室流浪貓」一段。

## 0. 總覽

| 項目 | 貓（現行） |
|---|---|
| 範圍 | 只住 **五樓**，一隻、全員共養 |
| 位置同步 | **不靠後端**：每 75 秒一個時段，依台北時間＋種子亂數算出位置，所有人算出來都一樣 |
| 互動 | 叫牠、摸摸、餵點心、逗貓棒、安靜陪伴、點碗加飼料／換水；做互動的人畫面是「本機覆蓋」，同時用事件讓**其他人也看到** |
| 進度 | 兩條：辦公室歸屬感（全員共用）＋個人信任度；每天每種互動有次數上限 |
| 美術 | AI（ChatGPT 網頁版）畫三視圖＋45° 斜角，合成 5 視角 × 10 姿勢圖集，貼在面向鏡頭的平面上 |
| 取名 | 全員提名＋投票，7 天後票數最高者定案 |
| 後端 | Cloudflare Worker／Durable Object：`pixelOfficeCat` 動作（進度、取名、互動事件） |

設計原則（寵物共通）：

1. **世界狀態要確定性**：沒有人互動時，所有人看到的寵物位置與動作必須一致，且不必花後端流量（時間表＋種子亂數）。
2. **互動是「覆蓋」**：做互動的人本機播放（寵物走向你再走回大家看到的位置），結束後無縫回到時間表；其他人靠事件重播。
3. **進度只增不減、每日上限**：避免洗進度，前端與 Worker 兩邊上限要一致。
4. **美術一律先定「設定稿」再補姿勢與角度**，確保花色、外框、比例一致。

## 1. 角色繪製（美術流程）

### 1.1 風格規範
- **賽璐珞（cel）風、Q 版、像素風顆粒感、暖黑色外框**（不是純黑，偏暖的深褐黑）。
- 毛的顆粒感保留，不要平塗；眼睛大而圓、頭身比 Q 版。
- 背景一律**單一純藍 #0066FF**（利於去背），**不要地面、投影、文字**；每張之間留足夠空白、不重疊。
- 同一份圖內的各視角**大小、頭身比例一致，腳底落在同一條水平線**。
- 貓的特徵（必須逐張一致）：三花（橘＋深褐虎斑＋白）、白色範圍（胸腹、四隻腳掌、臉部白斑）、粉色項圈＋金色鈴鐺、綠眼、粉耳。
  - 新寵物請先定義自己的「特徵清單」（花色、白色範圍、耳朵、配件）並寫進設定稿提示詞。

### 1.2 製作順序
1. **設定稿（三視圖）**：站立姿勢，由左到右「正面、右側（朝右）、背面」，3:1 橫幅。使用者確認後才進行下一步。
2. **其他姿勢的三視圖**：每個姿勢一張，同樣「正面／右側朝右／背面」3:1 橫幅。貓共 10 個姿勢（見 §1.3）。
3. **45° 斜角**：每個姿勢再補「右前斜 45°」「右後斜 45°」兩張，2:1 橫幅。
4. **下載 → 本機存放 → 跑圖集腳本 → 驗證 → commit**（見 §1.5）。

### 1.3 姿勢清單（貓）
`CAT_POSES = ['stand','walkA','walkB','sit','loaf','sleep','eat','run','groom','belly']`（順序＝圖集列順序，**不能亂改**）

| 姿勢 | 內容 | 用在 |
|---|---|---|
| stand | 站立（設定稿） | 預設、互動中站著、玩逗貓棒停頓 |
| walkA / walkB | 走路步伐 A（左前腳與右後腳向前）／B（另一組） | 走路、蹭腳；4.5 Hz 交替 |
| sit | 坐姿 | 門口、散步停點、茶水間吃完後 |
| loaf | 趴著四腳收起來（麵包貓） | 椅子、桌上睡覺 |
| sleep | 蜷起來睡（紙箱） | 紙箱內（y<0.3）的睡覺 |
| eat | 低頭吃東西（四腳站立、屁股微翹） | 茶水間吃飯、被餵點心 |
| run | 奔跑，四腳騰空 | 暴衝、被叫過來小跑步 |
| groom | 坐著舔前腳理毛 | 暴衝後裝沒事、坐著時每 18 秒中 6 秒 |
| belly | 躺下翻肚 | 逗貓棒結束 |

### 1.4 AI 生成提示詞（ChatGPT 網頁版，使用者的 Chrome）
**姿勢三視圖（範本，把「姿勢」那句換掉）**
> 請依照上傳的貓咪角色設定稿（花色、項圈與鈴鐺、像素風、暖黑色外框完全一致），畫同一隻貓的新姿勢，同樣是由左到右「正面、右側（朝右）、背面」三張一排的 3:1 橫幅。姿勢：〈走路，左前腳與右後腳向前邁出（步伐 A），尾巴微微翹起〉。要求：花紋、白色範圍、耳朵、項圈、鈴鐺與設定稿完全一致；三張大小與頭身比例一致，腳底落在同一條水平線上；背景為單一純藍色 #0066FF，不要地面、投影、文字；三張之間留足夠空白，不要重疊。

**45° 斜角（每個姿勢上傳該姿勢的三視圖後送出）**
> 請依照上傳的貓咪三視圖（花色、項圈與鈴鐺、像素風、毛的顆粒感、暖黑色外框完全一致），為「同一個姿勢」補兩個斜角度，由左到右排成一排 2:1 橫幅：第一張「右前斜 45 度」（身體轉 45 度，臉朝右前方，看得到正面與右側），第二張「右後斜 45 度」（身體轉 45 度，看得到背面與右側）。要求：花紋、白色範圍、耳朵、項圈、鈴鐺與三視圖完全一致；兩張貓的大小、頭身比例、姿勢與上傳圖一致，腳底落在同一條水平線上；背景為單一純藍色 #0066FF，不要地面、投影、文字；兩張之間留足夠空白，不要重疊。

操作經驗（用 Claude in Chrome 操作 ChatGPT）：
- 一個姿勢約 60～90 秒；同一個對話內連續做，檔案用 `file_upload` 上傳（要先 `find` 出檔案輸入的 ref），送出鈕在輸入框右下角。
- 下載：ChatGPT 頁面的下載鈕點了不一定存得到，改用頁面 JS 把圖片 `blob:` 抓下來、建立 `<a download>` 觸發下載（存到 ~/Downloads）。對話很長時 DOM 會「虛擬化」掉舊圖片，要用「最後一張 1774 寬」的圖，不要用數量判斷。
- 單次 `javascript_tool` 超過 45 秒會逾時，等待要拆成多次。
- 生成檔案尺寸：三視圖 2172×724（stand 是 2000×667 米色底）；斜角 1774×887。
- 每張生成後**逐張目視檢查**花色、項圈、鈴鐺、姿勢是否一致；不一致就請 ChatGPT 重畫。

### 1.5 圖集製作（`tools/build-cat-atlas.py`）
來源（**只存在本機、不進 Git**，被 `.git/info/exclude` 排除）：`pixel-plaza/ai-views/cat-sheets/`
- `<姿勢>-sheet.webp|png`：三視圖（正、側、背）
- `<姿勢>-q.png`：兩張斜角（前斜、後斜）

腳本做的事：
1. **去背**：藍底以 `b > r+70 且 b > g+25` 判斷；stand 是米色底，改用四邊洪水填滿。1px 開運算去雜點、小於 400 px 的區塊當雜點、填洞、**再腐蝕 1px 吃掉藍邊**。
2. **切格**：依左右空白分組（間隔 > 24 px）；三視圖要得到 3 組、斜角要得到 2 組，否則腳本中止。`run` 的正面與側面貼在一起，手動在 x=546 切開。
3. **縮放**：三視圖依 `SC = 0.34 × 2172 / 圖寬`（以圖寬正規化，因為 stand 圖比較窄）；斜角**以相鄰兩個視角的高度平均**為目標高度（前斜＝(正+側)/2、後斜＝(側+背)/2），所以轉向時大小不會忽大忽小。
4. **加外框**：`OUT = 7` 圖集像素的黑色粗外框（顏色 (26,20,16)），畫面上約 2～3 px。
5. **排版**：5 欄 × 10 列，每格 `CW×CH`（目前 391×253），貓**底部置中**，外框底緣離格底 4 px，所以**腳底離格底 4+OUT = 11 px**。
6. 輸出 `assets/cat/cat-atlas.webp`（無損）＋ `cat-atlas.json`（`cw, ch, poses, views, sc, foot, h`）。

圖集欄位順序（**角度由正面轉到背面**）：`['front','frontq','side','backq','back']` ＝ 0° / 45° / 90° / 135° / 180°。

**改了外框粗細或格子大小之後**：`index.html` 的 `CAT_CW / CAT_CH / CAT_FOOT` 要跟 `cat-atlas.json` 一致（`CAT_K = .0042` 是「世界單位 / 圖集像素」，決定貓在世界裡的大小，目前站立貓約 1 單位高）。

### 1.6 繪圖替換原則
- 換圖＝換來源檔 → 重跑腳本 → 圖集與 json 一起 commit（來源檔不進 Git，不見了就請 ChatGPT 依設定稿重畫）。
- 新增姿勢＝在 `POSES`／`CAT_POSES` 末端加一列（不要插在中間），圖集高度跟著增加，`catPose` 補上對應。

## 2. 角色在遊戲裡的呈現（渲染）

### 2.1 平面貼圖（billboard）
- `catBuild()` 建一片**垂直平面**（`PlaneGeometry` 乘 `CAT_K` 的格子大小），貼 `cat-atlas.webp`；平面**每幀轉向面對鏡頭**（`sp.rotation.y = toCam − catG.rotation.y`），高度用 `STRETCH` 補償鏡頭傾斜，腳底位置由 `CAT_FOOT` 算。
- 貼圖濾鏡 `LinearFilter`、不產生 mipmap；`tex.repeat = (1/5, 1/10)`，`tex.offset = (view/5, 1 − (row+1)/10)`。

### 2.2 視角選擇（`catPose`）
```
rel   = atan2(sin(貓朝向 − 朝鏡頭方向), cos(...))      // 貓相對鏡頭的角度
view  = round( atan2(|sin(rel)|, cos(rel)) / (π/4) )   // 0 正 / 1 前斜 / 2 側 / 3 後斜 / 4 背
mirror= (view 在 1..3) 且 sin(rel) < 0                 // 圖是朝畫面右邊，朝左就左右翻轉
```
- 圖片中側面與斜角都「朝右」，朝左一律用 `scale.x = −1` 鏡像。
- 狗或其他寵物只要遵守「圖朝右、由正面轉到背面」的欄位順序，就可以共用這段。

### 2.3 姿勢→圖格對應
- `walk` / `rub`：以 4.5 Hz 交替 `walkA`/`walkB`，走路時 y 有 0.03 的小彈跳。
- `run`：`run` 單張，加 0.14 的彈跳。
- `loaf`（共享狀態「睡覺」）：在紙箱（`y < 0.3`）用 `sleep`，椅子／桌上用 `loaf`；呼吸以 `scale.y` 1.6 Hz 正弦抖 ±1.2%。
- `eat`：`scale.y` 7 Hz 抖 ±1.5%（咀嚼感）。
- 其餘（`sit`、`groom`、`belly`、`stand`）同名；站立另有慢呼吸（1.8 Hz、±1%）。

### 2.4 頭上標籤
`cui-tag cat-tag`（DOM 元素跟著貓的螢幕位置）：顯示「名字」＋心情詞（優先序：`catHeld`（互動中的「♥／好吃／…」）＞ 睡覺 `zzZ` ＞ 吃飯 ＞ 暴衝 `！` ＞ 理毛）。鏡頭拉遠（貓離玩家 ≥ 9）且沒有 `catHeld` 時隱藏。

### 2.5 特效
- **愛心**：`catHeart()`，Canvas 做的 ♥ Sprite（粉紅填色＋黑外框），每顆往上飄 1.1 秒、左右擺動、後段淡出；`catHearts(n)` 每 320 ms 一顆。
- **點心**：`catTreatShow()`，手上與貓嘴前的黃色小球（半徑 .09）。
- **逗貓棒**：棒子（細圓柱，從手到球）＋紅球（`catToyShow`），球繞玩家甩動；見 §5.4。
- 所有特效 mesh 都標 `userData.noMask = true`（不被遮擋遮罩吃掉）。

| 物件 | 說明 |

| 貓碗 | `catBowlBuild(x,z)`：**兩個圓碗**（飼料＋水，`CylinderGeometry` 半徑 .21→.17、高 .14，藍色 `0x3a8fd0`，黑外框走 `HULL_LAYER`），碗內容物是扁圓柱（飼料棕 `0x9b6a3c`／水淺藍 `0x7fd0f2`），`visible` 由 `catBowlFull()/catWaterFull()` 控制；可點（`pick.kind='catbowl'`）。位置在茶水檯旁。 |

## 4. 角色機制

### 4.1 確定性時間表（`catAt` / `catPlan`）
- **時段**：`CAT.slot = 75000` ms；`s = floor(同步時間 / slot)`。同步時間 `syncNow()`＝本機時間＋與伺服器的時鐘差。
- **每個時段的計畫** `catPlan(s)`（以 `rng('cat:'+s)` 當種子、依歸屬感等級快取 `s:lv`，所以**同一時段所有人算出相同結果**）：
  - 台北時間 `tp = catTP(...)`（UTC+8）。
  - **休息時段**（<07:00、≥21:00、週六日）：權重 `box 6`；Lv≥1 加 `chair 3`。
  - **早上**（<10:30）：`door 6, tea 1, box 1`；Lv≥1 加 `wander 2, chair 1`。
  - **午餐**（11:30–14:30）：`tea 6, box 1`；Lv≥1 加 `chair 2, wander 1`。
  - **其他上班時間**：`box 2, tea 1, door 1`；Lv≥1 加 `chair 3, wander 2`；Lv≥2 加 `desk 2`。
  - 加權抽籤決定 `kind`；`chair`／`desk` 沒有可用點就退回 `box`。
  - `wander`：隨機 1～2 個途經散步點，最後在一個散步點坐下（朝向隨機）。
  - **暴衝**：非休息時段，機率 12%（家貓等級 24%）：到定點後等 `zt = 20～40` 秒，跑兩個散步點再跑回來，然後坐下理毛 8 秒。
  - `delay = 0～12` 秒（每個時段開始後晚一點才出發，避免整齊劃一）。
- **移動**：路線由 `findPath`（A*）串起來並快取（`catPaths`，上限 120）；速度 `max(CAT.walk(1.7), 路線長度/40)`，所以長路線會走快一點；起落點 0.6 秒內把 `y` 內插到停點高度（跳上椅子、桌子）。
- **停點姿勢**：`sPos.pose`；在 `tea` 停超過 22 秒改 `sit`；`sit` 時每 18 秒中前 6 秒做 `groom`；`tea` 的 `eat` 在碗空時改 `sit`。
- ⚠️ **改 `catPlan` 權重或 `CAT.slot` 會讓新舊版本的貓位置不同**，改完請使用者全員重新整理。

### 4.2 碗
- 飼料碗與水碗各自記「最後補充時間」（`catOffice.bowlAt / waterAt`），**8 小時內算滿**；**週末與休息日有自動餵食器，碗視為一直滿的**。
- 碗是否滿影響：貓去茶水間時是否做 `eat`、碗裡的內容物是否顯示。

### 4.3 兩條進度
| | 辦公室歸屬感（全員共用） | 個人信任度 |
|---|---|---|
| 等級 | 路過 → 常客 → 室友 → 家貓；門檻 `CAT_LV_AT = [0,30,80,160]` | 陌生 → 好奇 → 熟悉 → 親近；門檻 `TRUST_AT = [0,10,25,50]`，上限 100 |
| 影響 | 活動範圍（常客：空椅子與散步；室友：空桌；家貓：更常暴衝） | 叫牠會不會來、會不會玩逗貓棒、登入後會不會走來蹭你、要不要先聞再吃點心 |

增益表（**前端 `CAT_GAIN` 與 Worker `CAT_CARE` 要同步改**）：

| 互動 | 信任 | 歸屬 | 每日上限 |
|---|---|---|---|
| feed（餵食：加飼料／換水） | +1 | +3 | 2 |
| treat（點心） | +4 | +1 | 3 |
| play（逗貓棒） | +3 | +1 | 3 |
| company（安靜陪伴） | +2 | 0 | 2 |
| pet（摸摸） | +1 | 0 | 3 |

- 超過上限仍可互動（有動畫），只是不再增加進度；進度**只增不減**。
- 每天依台北日期換日（`catRollDay`）。
- 升級時跳一次提示（用 localStorage 記已看過的等級）。

### 4.4 情緒狀態（本機）
- `catAnnoyed`：被吵醒或被拒絕後的「不爽」截止時間，期間任何互動（除了「叫牠」）都被拒絕（「牠現在不想理你」）。
- `catGreeted`：登入後第一次，若信任度 ≥ 2、累積餵食＋點心 ≥ 3 次、貓睡著以外、玩家在五樓且離貓 > 6，貓會主動走來蹭你一次（本機）。

## 5. 角色功能（互動）

所有互動共通前置：要登入（否則提示「登入後才會累積和貓的感情」，仍有動畫但不計進度）；玩家狀態不能是離開（`AWAY`）；除「叫牠」外要離貓 ≤ 4.5（不然提示「走近一點再試試」）。

### 5.1 叫牠過來（call）
- 睡著：「牠睡得很熟，只動了動耳朵」。
- 信任 ≥ 熟悉：小跑步（走路速度 ×2.4）到玩家前 1.0，`look` 3 秒＋`♥`。
- 信任 = 好奇：40% 機率慢慢靠過來到 1.8 處，否則回頭看一眼。
- 信任 = 陌生：只回頭看一眼。

### 5.2 摸摸（pet）
- 睡著時摸：貓換地方睡，不爽 60 秒。
- 陌生 50% 機率閃開走掉（不爽 20 秒）。
- 一般流程（2026-11-04 起有互動感）：**貓先走到玩家腳邊（+.35, +.85）→ `rub` 3 秒繞腳八字形蹭 → 飄 4 顆愛心＋標籤 ♥ → 計進度**，玩家自動面向貓 3.6 秒。

### 5.3 餵點心（treat）
- 睡著：「等牠醒來再餵」；當日已 3 次：「吃飽了，牠拒絕了點心」。
- 流程：貓走到玩家旁（+.6, +.8）→ 玩家手上出現點心球 → 貓 `sniff` 2.2 秒 → 信任 ≥ 好奇或 55% 機率吃：`eat` 3.2 秒、飄 2 顆愛心、計進度；不吃：貓走開、不爽 15 秒、點心收回。

### 5.4 逗貓棒（play）
- 要信任 ≥ 好奇（陌生只瞄一眼）；睡著不行；當日上限同表。
- 流程：貓進入 `play` 模式 6 秒——玩家手上出現棒子，**紅球繞玩家甩動**（`ang = 時間×2.1`，半徑 ~1.7×1.5，球遇障礙會換角度、最後退回玩家面前 .9），貓追著球跑（速度 4.2）、到了就站立彈跳，**6 秒後翻肚（`belly`）2.2 秒**；玩家全程面向貓。

### 5.5 安靜陪伴（company）
- 玩家不要走動 20 秒（移動 > 1.2 或貓離 > 4.5 或被其他本機動作打斷就中斷：「陪伴中斷了」）。
- 流程：貓走到玩家旁（+.9, +.5）→ `stay` 模式：`sit`，**約 9 秒後趴下（`loaf`）**，面向玩家；每 ~3.2 秒飄一顆愛心；完成時 3 顆愛心、貓走回原本行程、計進度。

### 5.6 點碗（bowl）
- 離碗 > 3.2：玩家自動走向碗邊（提示「走到碗邊再點一次」）。
- 飼料空了 → 加飼料（算 feed，`effect:'food'`）；否則水空了 → 換水（`effect:'water'`）；都滿：「碗裡還滿滿的」。
- **不需要從冰箱拿東西**（2026-11-04 起；冰箱「貓咪專用區」與庫存已移除）。

### 5.7 面板（點貓開啟）
- 位置與冰箱面板相同（底部置中），玻璃卡片，叉叉鈕是 34×34 正圓靠右上；**點面板外面、Esc、走出 7 單位外都會自動收起**。
- 內容：兩條進度條、「牠現在：…」、五顆動作鈕（叫牠過來／摸摸／餵點心／逗貓棒／安靜陪伴，點心與逗貓棒右上角黃字＝今天剩餘次數，用完變灰）、取名投票區、今日剩餘次數說明（含雲端存檔狀態）。

### 5.7.1 當日提示文字（`fr-note`）
「今天還能增加：點心 N　逗貓 N　摸摸 N　陪伴 N　餵食 N。貓碗在茶水間旁，點碗就會加飼料和換水。」

### 5.8 本機互動覆蓋（`catLocal`）
- 模式：`go`（走向某點）、`return`（走回時間表位置）、`rub`、`sniff`、`look`、`eat`、`belly`、`play`、`stay`；用 `catStep(dt, now)` 推進。
- 結束一律 `catReturn()`：A* 走回「大家看到的位置」（時間表），重試 < 4 次，失敗就直接接回。
- 沒有 `catLocal` 時，貓位置以 `k = min(1, dt×12)` 平滑逼近 `catAt()`。

## 6. 多人同步

### 6.1 預設：不同步（時間表）
只要沒人互動，所有人用同一套時間表算出同樣的貓，**零網路流量**。

### 6.2 互動事件（2026-11-05 起，全員看得到）
- 互動者送 `pixelOfficeCat {op:'act', kind:'pet|treat|play|company'}`（`catActOut`）；Worker 存 `cat:office.act = {name, kind, at}`（只保留 5 分鐘），**隨 `pixelOfficeState` 每次輪詢／推送一起回傳**（`unchanged` 回應也帶）。
- 其他人收到 `act`（`catActIn`）：同在五樓、事件 ≤ 6 秒、貓沒有在做本機互動、離那位同仁 ≤ 14 → 貓走向**那位同仁**播同樣動作（愛心、點心、逗貓棒、陪伴）。重播**不計進度、不顯示對話框**；第一次讀到的舊事件略過。
- `catPlayerPos()` 會回傳「夥伴」（`catPartner`，有 `catPartnerUntil` 期限）的位置，所以重播時貓的動作對準的是那位同仁而不是自己；自己做互動時（`catAct`）先 `catPartner = null`。
- **Worker 沒部署時**：自己的畫面照常，別人看不到。

### 6.3 即時位置（與寵物無關，但共用通道）
玩家位置走 WebSocket（`/ws` 的 `hello`＋`p`），見 `MAINTENANCE_LOG.md` 2026-11-05 條目；寵物事件目前走 HTTP 輪詢＋既有的 `pixel` 推送通知。

## 10. 第二款寵物（狗）：與貓不同之處與建議做法

> 本章是**設計建議**（尚未實作），目的是讓狗的習慣有不同的呈現，同時沿用貓的架構。

### 10.1 行為習慣對照

| 面向 | 貓（現行） | 狗（建議） |
|---|---|---|
| 與人的關係 | 獨立、愛理不理，要靠信任度才親近 | **黏人**：認得人、會跟著主人（熟的人）走，看到人會跑過來 |
| 一天作息 | 紙箱睡、門口坐、午餐茶水間、散步 | **早上在門口迎接**同事上班、日間窩在狗窩、午餐吃飯、傍晚在門口等下班；下班後睡窩 |
| 移動 | 走路慢、偶爾暴衝 | 走路比貓快、常小跑；**跟隨**時追著人 |
| 互動回應 | 常拒絕（不爽、閃開） | 幾乎不拒絕；**信任度低只是比較害羞**，不會生氣走開 |
| 玩耍 | 逗貓棒（追球、翻肚） | **丟球撿回（fetch）**、握手／坐下／趴下口令、搖尾巴 |
| 吃東西 | 碗、點心（會挑） | 碗、點心（**一定吃**，所以「吃飽上限」更重要）；餵食後會討摸 |
| 聲音／表情 | `♥`、`zzZ` | 汪（頭上 `汪！`）、舌頭外露、尾巴搖擺 |
| 需求 | 無 | **散步需求**：每天要有人帶出去（可做成每日任務，完成加歸屬感） |

### 10.2 必須改變的機制
1. **位置同步**：貓用「所有人算出一樣的時間表」。狗會**跟隨特定玩家**，位置取決於玩家，沒辦法純確定性。建議：
   - 沒人理牠時沿用時間表（門口、窩、碗、散步）。
   - 有玩家「帶牠」時，狗跟隨該玩家（靠玩家位置已經有的即時通道），其他人看到狗跟著那個玩家走：**用互動事件（`act`）＋被跟隨者的玩家位置推算**（狗的位置＝被跟隨者身後 N 單位，後面做路徑平滑），不需要新增位置同步通道。
   - 事件要有「開始跟隨／結束跟隨」兩種，並設逾時（沒更新 30 秒自動結束）。
2. **互動事件**要擴充 kind：`call`（叫過來）、`fetch`、`sit`（口令）、`follow`、`walk`（散步）。事件資料可加 `target`（被跟隨者名字）。
3. **姿勢清單**：stand、walkA、walkB、run（常用，要有跑步循環）、sit、down（趴下）、sleep（窩裡）、eat、**tail-wag（搖尾巴）**、**fetch（叼球）**、**play-bow（前趴屁股翹）**、**beg（作揖）**、**paw（握手）**。姿勢數量比貓多，圖集可能要 **>10 列**；列數與順序要寫在 `POSES` 並同步 json。
4. **視角**：沿用 5 視角（正、前斜、側、後斜、背）；狗的奔跑與叼球側面特別重要，可把 `run` 的比重放大。
5. **進度**：沿用「歸屬感（全員）＋信任度（個人）」兩條，但**意義改成「忠誠度」**：信任高的人，狗看到你會主動跑來、會跟著你；信任低的人，狗只是遠遠看著（不是生氣）。`CAT_GAIN` 對應表請另訂 `DOG_GAIN`（例如 walk、fetch、treat、pet、feed、train），**每日上限仍要有**。
6. **後端**：不要複製貼上 `cat:`。建議**參數化**成 `pet:<寵物id>:<名字>`／`pet:<寵物id>:office`／`pet:<寵物id>:name`，`pixelOfficeCat` 改成 `pixelOfficePet {pet:'cat'|'dog', ...}`；取名投票（`cat-naming.ts`）本來就與物種無關，可直接共用，只要 key 加上寵物 id。
7. **碗**：狗的碗外型不同（可用同一套 `Cylinder` 但尺寸、顏色不同），位置不同，但「8 小時算滿、週末自動餵食器」可沿用。
8. **窩**：狗窩取代紙箱，用 `fitsBox` 找位置。
9. **門口迎接**：貓只是「在門口坐」；狗要有「上班時間（08:00 前後）見到玩家登入就跑過來」的行為。可用**玩家進入五樓／電梯開門**當觸發，並走本機覆蓋（不用同步）。

### 10.3 可以直接沿用的部分
- 美術流程（§1）：設定稿 → 姿勢三視圖 → 45° 斜角 → 腳本合成。
- 圖集格式、`catPose` 視角選擇與鏡像、billboard 渲染、頭上標籤、愛心／點心／道具特效。
- 本機互動覆蓋（`catLocal` 的 `go / return / look / ...` 模式機）、`catPartner` 重播機制。
- 進度算法（`catRollDay`、只增不減、取較大值合併）、取名投票。
- 面板版型、關閉行為、除錯入口。

### 10.4 建議的程式重構（做第二隻寵物之前）
把貓的程式抽成一個「寵物設定物件」，再寫一個通用 `Pet` 類別，貓與狗各自只提供設定：
```js
const PETS = {
  cat: { id:'cat', name:'無名小貓', atlas:'assets/cat/cat-atlas.webp', json:'assets/cat/cat-atlas.json',
         poses:[...], gain:{...}, schedule:catPlan, behaviors:{...}, speeds:{walk:1.7, run:7.5}, slot:75000 },
  dog: { id:'dog', ... follow:true, ... }
};
```
- 抽出：`petBuild`（billboard）、`petPose`（視角與姿勢→圖格）、`petStep`（本機覆蓋模式機）、`petCare`（進度）、`petPanel`（面板）、`petActOut/In`（事件）。
- 每隻寵物的差異只放在：姿勢→動作對應、時間表、可用互動清單、增益表、特效。
- 全域狀態（`catG`、`catLocal`、`catState`…）改成 `pet.g / pet.local / pet.state`，避免兩隻寵物互相覆蓋。
- 這個重構要**一次只做一件事**：先重構（行為不變）、驗證貓不受影響，再加狗。

## 12. 已知限制與還沒做的事

- 只住五樓；四樓沒有貓。
- 陽光／安靜程度／桌面擺設影響睡哪張桌子；貓的專屬圖鑑——都還沒做。
- 取名投票的管理者判斷與位置更新一樣**沒有真正驗證身分**。
- 互動事件靠輪詢／推送通知，別人看到的互動比操作者晚數百毫秒到 1 秒；重播時貓可能從不同位置起步（貓的時間表位置在各端一致，所以起步點相同，但路徑重算）。
- 本機預覽的瀏覽器窗格幀率低，肉眼無法確認動畫順暢度，需到正式站實測。
- 45° 斜角圖由 AI 生成，不同姿勢之間的細節（例如鬍鬚、腳掌）可能略有差異；若某個角度看起來怪，重畫該姿勢的斜角、重跑腳本即可。
