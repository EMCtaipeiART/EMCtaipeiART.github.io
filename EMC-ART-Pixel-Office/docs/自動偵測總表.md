# 像素辦公室｜自動偵測總表

> 最後更新：2026-09-22。所有時間都是**台北時間**。
> 數值全部對應程式裡的常數，改程式時請一併更新這份表。

---

## 一、每分鐘在跑的兩件事

| 誰 | 頻率 | 做什麼 |
| --- | --- | --- |
| **設計師電腦的爬蟲**（`scripts/nas_design_image_watcher.mjs`，本機 cron） | 每分鐘 | ①回報「這台電腦開著」＋**鍵鼠閒置了幾秒** ②掃描 NAS 設計圖 |
| **Worker 排程**（Cloudflare cron） | 每分鐘 | ①寄出排程信 ②**同步 Google 行事曆** |

心跳與 NAS 無關：NAS 沒連上、沒有案件要掃，心跳照樣送（電腦開著本身就是重點）。

---

## 二、電腦開著時，狀態怎麼判斷

心跳進來時由 `pixelOfficeWorkStatus()` 決定，**由上往下第一個成立的就是結果**：

| 判斷順序 | 條件 | 狀態 |
| --- | --- | --- |
| 1 | 週六日、國定假日（含補假）——就算電腦開著 | **下班** |
| 2 | 閒置 ≥ 5 分鐘，且 **12:00–13:59** | **用餐** |
| 3 | 閒置 ≥ 5 分鐘，其他時間 | **廁所** |
| 4 | **19:00–05:59**，人在電腦前 | **加班** |
| 5 | 其餘時間，人在電腦前 | **在座** |

- 閒置判斷排在時間判斷前面：人不在電腦前就不算還在工作，所以晚上離開座位五分鐘會從加班變廁所，回來打字又變回加班。
- 閒置秒數只支援 **macOS 與 Windows**；其他系統不回報，就永遠當作「人在電腦前」。
- **關機或睡眠一律是下班**，不是用餐或廁所——用餐與廁所的定義都是「電腦開著、人不在」。

## 三、關機偵測

| 項目 | 值 |
| --- | --- |
| 多久沒心跳算關機 | **5 分鐘**（容許漏報 4 次，避免網路小卡頓就誤判） |
| 檢查時機 | 每次有人讀取狀態時（遊戲畫面每 3 秒會讀一次） |
| 會被改成下班的狀態 | 在座、加班、用餐、廁所 |
| 不會被動到 | 會議、休假、出國、公出 |

## 四、Google 行事曆同步

| 項目 | 值 |
| --- | --- |
| 頻率 | 每分鐘 |
| **只在這個時段查** | **平日 08:00–21:59**（假日與其他時間完全不查，省 API 配額） |
| 查詢範圍 | 「現在這一分鐘」 |
| 用誰的授權 | `machi.chen@emctaipei.com` 一個人的（其他四位不必連接任何東西） |
| 判定為**會議** | 忙碌中，且該段忙碌 **不超過 4 小時** |
| 判定為**休假** | Google 原生「不在辦公室」事件，或標題含請假關鍵字（休假／請假／特休／年假／補休／病假／事假…） |
| 忽略 | 超過 4 小時的忙碌（多半是整天的特休，不擋的話會整天掛著「會議中」） |

**晚上 22:00 之後、隔天 08:00 之前的會議不會被偵測到。**

## 七、手動點的狀態會怎樣

| 你手動點的 | 行事曆有會議／休假時 | 什麼時候回到自動 |
| --- | --- | --- |
| 在座、加班、用餐、廁所、下班 | **會被蓋掉** | 行事曆覆蓋、跨時段（白天↔晚上↔假日）、或電腦關機重開 |
| 公出、出國、會議、休假 | **保留不動** | 只有電腦關機重開，或自己改掉 |

**想立刻交還給電腦判斷**：送 `pixelOfficeUpdate` 的 `patch.status = "auto"`（不是一種狀態，是出口），會清掉手動標記並套用當下該有的狀態。

## 九、其他背景排程

| 項目 | 頻率 | 說明 |
| --- | --- | --- |
| 爬蟲自動更新檢查 | 每 **10 分鐘** | 讀 GitHub 上的發布清單，版本不同才下載（失敗 2 分鐘後重試） |
| 設計需求系統背景刷新 | 每 **6 秒** | 條件請求，內容沒變走 304（幾乎不耗流量）；每 **30 秒** 一次完整刷新 |
| 等級／案件快照（`database_archive.json`） | 每小時 **第 17 分** | 人物資料卡的等級與案件量由它提供，所以最多會落後一小時。**「手上的案件」只算還在現行資料庫的**——快照裡有早就歸檔、當初忘了改成已完成的舊案件，那些資料改不動，不濾掉會一直被算進案量（用快照自帶的 `currentDatabaseRowKeys` 過濾）。等級與分數仍用完整歷史資料。 |

## 十、怎麼查問題

```bash
curl -s -X POST https://machi-design-api.machi-chen.workers.dev/api \
  -H 'Content-Type: text/plain;charset=UTF-8' \
  -d '{"action":"pixelOfficeCalendarStatus","serviceKey":"<NAS_WATCHER_API_KEY>"}'
```

回傳裡的重點欄位：

| 欄位 | 看什麼 |
| --- | --- |
| `heartbeats` | 每台電腦最後一次心跳、是否在線。**「電腦明明開著卻顯示下班」先看這裡** |
| `last.detected` | 行事曆判定每個人現在應該是什麼狀態 |
| `last.manualHeld` | 偵測到了，但因為手動狀態而沒套用的人 |
| `last.unreadable` | 行事曆讀不到的人（權限問題） |
| `canReadCalendar` | 授權有沒有包含行事曆範圍 |

`detected` 有值但 `manualHeld` 也有那個人 → 是被手動狀態擋住，不是偵測失敗。
